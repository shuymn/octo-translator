# Decisions

Which libraries octo-translator uses, and the patterns the code follows. The security invariants these decisions keep
are in [threat-model.md](threat-model.md); the IDs below refer to it.

The balance: a dependency is taken where writing the code ourselves would be maintenance without a security or product
reason, and refused where the exact rule is the point (the marker format, the GitHub selectors) or where a library would
mostly add bundle size to a single call. Security mechanisms use an established implementation (SUP-1).

## Stages

Status is _In use_ when the code uses it, and _Planned (n)_ when it is decided for a stage that does not exist yet:

1. **Providers in the extension:** a Responses API client (DeepSeek, OpenAI) beside the Gemini client, with the
   provider, model and thinking level chosen in the options; `deepseek-flash` without thinking by default. _In use._
2. **Translation on Cloudflare:** a Worker that translates on request and stores translations in D1, and translates the
   owner's own English pull requests ahead of time, found by a scheduled GitHub search and narrowed by a CEL expression.
   _In progress:_ the Worker package, its routing, AUTH-1, the translate route with D1, the extension's Worker client (with a local fallback), the segments of a pull request made from the REST API (DOM-3) and the scheduled ahead-of-time translation with its CEL filter are in use; the deploy setup and AI Gateway are not.
3. **Repository wiki:** a Pi Durable agent per GitHub repository, in a Durable Object, that keeps a markdown wiki
   (glossary, overview, module pages) in that object's SQLite, gives glossary lines to every translation, and translates
   with repository context on request.

| Once per version across overlapping runs  | A lease on the whole run, a claim per version in D1, a Durable Object as the single runner                     | A claim per version in D1, versions ordered by when they were fetched, and a cursor that moves forward only past finished pull requests | In use      | Cloudflare does not promise that cron invocations never overlap, and retries a failed one. ## Patterns

| Concern     | Pattern                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Results     | A discriminated union, `{ ok: true, ... }` or `{ ok: false, code }`, with the code from a closed set (`TRANSLATION_ERRORS`). User-facing text for each code is a `Record` table in `controller.ts`. The Worker (2) answers a translation's outcome as that same `TranslationResult`, with status 200, so the extension handles a local and a remote translation alike; the Worker's own refusals (authentication, routing, a malformed or oversized body, an unsupported choice) are codes from `WORKER_ERRORS` with the HTTP status of each in a `Record` in `worker/src/http.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Worker      | With a Worker URL and service token saved, the background asks the Worker on a local cache miss and caches its translation locally (`createTranslateService`). Each way the Worker can fail is a member of `WORKER_FAILURES` in `src/lib/worker-client.ts`, and `WORKER_FAILURE_HANDLING` says per member whether to translate locally and which `TranslationError` to answer otherwise: only an unreachable Worker (network failure or timeout, also while the body is read, or 5xx) falls back, and only with a local key (else `worker-unreachable`); a refusal (401, 403, 429, another 4xx, a redirect) answers `worker-rejected`, which the page explains with a link to the options, because a silent fallback would hide a broken setup. The URL is an https origin only (`parseWorkerUrl`): one origin for the token and for the host permission, with the route fixed in the client. MV3 needs a host permission for the background's cross-origin `fetch` (https://developer.chrome.com/docs/extensions/develop/concepts/network-requests); the origin is the owner's, so the manifest declares `https://*/*` as optional and the options page requests the one origin inside the save click, as `permissions.request` requires a user gesture (https://developer.chrome.com/docs/extensions/reference/api/permissions), refusing to save when it is denied and removing a replaced origin's grant. The origin, client id and secret are one item beside the API keys (`workerAccessItem`, KEY-1), written whole and read once per request, so a token is never paired with another origin; an options page writes it, and requests or drops a permission, only when its Worker section was edited (`planWorkerSave`, `storeWorker` in `src/lib/worker-edits.ts`), the stale-tab rule `editedKeys` applies to the keys. |
