# Decisions

Which libraries octo-translator uses, and the patterns the code follows. The security invariants these decisions keep
are in [threat-model.md](threat-model.md); the IDs below refer to it.

The balance: a dependency is taken where writing the code ourselves would be maintenance without a security or product
reason, and refused where the exact rule is the point (the marker format, the GitHub selectors) or where a library would
mostly add bundle size to a single call. Security mechanisms use an established implementation (SUP-1).

## Stages

Status is _In use_ when the code uses it, and _Planned (n)_ when it is decided for a stage that does not exist yet:

1. **Providers in the extension:** a Responses API client (DeepSeek, OpenAI) beside the Gemini client, with the
   provider, model and thinking level chosen in the options; `deepseek-flash` without thinking by default. _In use._
2. **Translation on Cloudflare:** a Worker that translates on request and stores translations in D1, and translates the
   owner's own English pull requests ahead of time, found by a scheduled GitHub search and narrowed by a CEL expression.
3. **Repository wiki:** a Pi Durable agent per GitHub repository, in a Durable Object, that keeps a markdown wiki
   (glossary, overview, module pages) in that object's SQLite, gives glossary lines to every translation, and translates
   with repository context on request.

## Patterns

| Concern     | Pattern                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Results     | A discriminated union, `{ ok: true, ... }` or `{ ok: false, code }`, with the code from a closed set (`TRANSLATION_ERRORS`). User-facing text for each code is a `Record` table in `controller.ts`. The Worker (2) answers the same result type, so the extension handles a local and a remote translation alike.                                                                                                                                                                                                   |
| Closed sets | An `as const` array and the union derived from it (`TRANSLATION_ERRORS`, `SEGMENT_KINDS`, `PROVIDERS`, `THINKING_LEVELS`); per-member handling is a `Record` table, so a missing member does not compile.                                                                                                                                                                                                                                                                                                           |
| Providers   | `src/lib/providers.ts` is data only: each provider's label, models, the thinking levels each model takes and where its key is made. The options offer only those combinations and refuse others on save (`parseChoice`); a stored choice is checked again when read (`resolveChoice`), falling back to the provider's default. The clients are dispatched from a `Record` in `src/lib/clients.ts`, so the content script can name a provider without bundling them.                                                 |
| GitHub DOM  | Every selector is in `src/lib/pr-page.ts`. GitHub changes its markup without notice; a broken selector is fixed there.                                                                                                                                                                                                                                                                                                                                                                                              |
| Controls    | `src/lib/controls.ts` builds them from GitHub's own classes: a button among the description's header actions (`aria-pressed` while the translation shows, a spinner while it is requested), a note on the header's "commented" line like GitHub's "edited", and a `flash-warn` above the description on errors. A visually hidden `role="status"` announces each change. Without the header actions, a notice above the description carries all of it. Spinners are not `octicon`s: GitHub's CSS fills those.       |
| Page sync   | `PageController.sync` is idempotent and runs once per animation frame after any mutation. It compares the page with its state and changes only what differs, so GitHub's re-renders and its own changes settle.                                                                                                                                                                                                                                                                                                     |
| React nodes | The title belongs to GitHub's React tree. Its nodes are never replaced or edited: a copy carrying the translation is placed next to it and the original is hidden.                                                                                                                                                                                                                                                                                                                                                  |
| Rails nodes | The description is server-rendered. Its inline runs are swapped with translated nodes, and the original nodes are kept to swap back.                                                                                                                                                                                                                                                                                                                                                                                |
| Boundaries  | The content script reads the page and settings; the background holds the API keys, the cache and the only network request. Messages are Valibot schemas in `src/lib/messages.ts`, checked on both sides. With the Worker (2), the background sends the same segments to the Worker instead of a model.                                                                                                                                                                                                              |
| Testability | Modules under `src/lib` take their dependencies (`fetch`, storage, the translate call) as arguments; the entry points under `src/entrypoints` only wire them to the extension APIs (the background's message handling is `createMessageHandler` in `src/lib/message-handler.ts`). A security invariant is pinned first by a test that runs the code (the content script's storage reads run on WXT's fake browser), and by source analysis second. The Worker (2) and the Durable Object (3) follow the same split. |
| Agent tools | (3) Every tool the agent has is a Pi extension tool with a Valibot-checked input. Tools that only read are `replay: "safe"`. The only tool that writes is the wiki page writer, and it exists only in sessions that ingest trusted sources (WIKI-1).                                                                                                                                                                                                                                                                |
